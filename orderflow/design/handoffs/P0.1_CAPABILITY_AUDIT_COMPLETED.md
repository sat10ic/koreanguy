## What could NOT be verified — the honest unknowns

Live access was withheld by the task (correctly, per R7/R1 design). Until the
owner's live run:

1. **Unverified: the feed's real depth cadence.** All medians/histograms in
   `capability.json` are synthetic by construction. The R1 gate table (5s/15s
   window validity) stays unanswered.
2. **Unverified: 50-level TBT provisioning.** Confirmed by protocol reading
   that the standard data socket carries only 5 levels (official client
   source) and that TBT is a separate protobuf socket
   (`rtsocket-api.fyers.in`, URL provisioned via an authenticated REST call).
   Whether THIS account is provisioned can only be answered by an owner-run
   TBT session. The external review's claim remains a claim.
3. **Unverified: adapter field mapping against live decoded traffic.** The
   mapping is Certain as far as the official `fyers-apiv3` v3.1.16 wheel
   source goes (read from the published wheel, not memory); the epoch
   semantics of `exch_feed_time` (assumed UTC epoch seconds, IST string
   fallback) and the 1-second timestamp granularity are assumptions the first
   live session must confirm. A wrong mapping would surface as R5 nulls, not
   silent zeros.
4. **Unverified: real subscription limits.** The enforced ceiling was not and
   cannot be established offline; the synthetic rejection only proves the
   measurement path. Documented batch limit (5000 symbols) is carried as an
   external claim with its source.
5. **Unverified: live reconnect behaviour** (real disconnect cadence, ack
   timing, token expiry mid-session) — the manager logic is test-verified
   against forced disconnects, the production socket is not.
6. **Environment note:** the default `python` on PATH (a 3.14 hybrid install)
   ignores cwd/PYTHONPATH for `-m` invocation; the CLI was run with the
   Python 3.12 interpreter. Tests run fine under either via
   `python -m pytest`.
