## Contract to implement

Add `GET /api/radar?days=30&min_traders=2`.

- `days` integer range 1–730; default 30.
- `min_traders` integer range 1–17; default 2.
- Source mention kinds are exactly `trade_event`, `watch_idea`, `theme`.
- Read symbols from the strictly parsed JSON array in the existing
  `post_class.symbols` TEXT column; normalize to
  uppercase, trim whitespace and a leading `#`, reject empty/non-string values.
- One post-symbol pair is one mention even if the array repeats it.
- Normalize handles by trimming a leading `@` and compare case-insensitively.
- A symbol is validated only when at least one `daily_prices` row exists.
- Ranked results include validated symbols only. Unvalidated symbol counts and
  names are returned separately as coverage debt.
- For each symbol return total mentions, distinct traders, first/last timestamp,
  strongest rolling seven-calendar-day cluster, and chronological evidence.
- Each evidence item includes `post_id`, `handle`, `ts_utc`, `url`, exact post
  `text`, classifier `kind`, and classifier `confidence`.
- All day windows use Asia/Kolkata calendar dates derived from `ts_utc`; a post
  near UTC midnight belongs to the IST date visible throughout TraderLog.
- Strongest cluster: maximize distinct normalized traders, then mention count,
  then most recent cluster end; implement deterministically and document ties.
  Its `start_date` and `end_date` are the actual inclusive seven-day window
  boundaries (`end_date - 6 days` through `end_date`), not merely the first and
  last dates on which a mention happened inside that window.
- Rank symbols by cluster trader count descending, cluster end descending,
  total distinct traders descending, then symbol ascending.
- The payload carries `is_mock`, requested filters, classified eligible-post
  count, included mention count, invalid JSON count, and unvalidated mention
  count. Missing/invalid data is counted, never silently coerced.
- Call the observable `co_attention`; do not use `consensus`, `correct`, `win`,
  `hot`, or an invented score in API names or copy.

The derive module must be pure over supplied rows so unit tests do not touch the
production DB. `api/app.py` remains HTTP wiring and row selection.
