## UI contract

- Visible nav label and route key are `RADAR`. A legacy `?tab=IDEAS` URL maps to
  `RADAR` instead of breaking; new URLs write `?tab=RADAR`.
- Add the named client `fetchRadar(params)`; no generic client or second endpoint.
- Controls: 7/30/90 day window and minimum 2/3/4 distinct traders. Changing a
  control refetches and never filters a stale payload client-side.
- Desktop composition: centered 1680px grid at 1920×1080. A ranked symbol table
  occupies the primary column; a selected-symbol evidence rail occupies the
  secondary column. Use one structural border per major region and internal
  hairlines, never nested cards.
- Table columns: symbol, strongest seven-day cluster trader count, total distinct
  traders, mentions, last mention. Default selection is the first ranked row;
  selection works via button/keyboard and is visually/semantically exposed.
- Evidence rail: cluster date range/count stated in words, then exact source
  items with handle, timestamp, classifier kind, confidence, exact post text,
  and external source link. Use the quiet vertical rail as the non-tabular visual;
  do not add a decorative chart.
- Coverage footer exposes every coverage counter and the unvalidated symbol
  names. Unvalidated symbols never appear in ranked rows.
- Use `co-attention`; never label bare mentions consensus, hot, correct, win,
  accuracy, bullish, or bearish.
- Mono is restricted to symbols, dates, counts and confidence. Prose is sentence
  case. Interaction uses the existing blue token; amber only marks coverage
  debt; no raw color literal outside `tokens.css`.
- Zero results and errors are compact explanatory states, not framed empty charts.
- Do not render Themes or Setups placeholders in this slice.
