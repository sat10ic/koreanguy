# UX Audit — unidesk_terminal — 2026-08-31

Scope: read-only. Read the integration plan (`unidesk/design/UI_BACKEND_INTEGRATION_PLAN.md`),
`fixtures.ts`, `tonight.ts`, every screen under `src/screens/`, and the widgets they use.
Wireframe reference: `plan/UNIFIED_DESK_UI_UX_MANUAL_V2.md` (cited inline where a screen
comment names a section, since the manual sections weren't independently re-diffed
element-by-element in this pass — see caveat below).

Caveat: I did not do a line-by-line diff of every screen against the full text of
`UNIFIED_DESK_UI_UX_MANUAL_V2.md` (didn't open that file directly — only the section refs
embedded as comments in the screen source). **Unverified: whether the built screens match
the manual's actual prose beyond what the code comments claim to implement.** Treat the
"wireframe fidelity" angle below as based on the code's own citations, not an independent
manual read.

## Tonight (`src/screens/Tonight.tsx`)

**User CAN:** see session date/as-of, universe scanned/skipped, EMA21/EMA50 breadth counts
(`Tonight.tsx:76-93`); see 268 real candidates grouped by detector with an ScrollRail per
setup type (`Tonight.tsx:111-129`); see a "Blocked/Review" chip on non-rankable detector
groups (`Tonight.tsx:118-120`); see the real honesty footer (`Tonight.tsx:165`, sourced from
`REAL_HONESTY_FOOTER` in `tonight.ts:161-167`); see a session picker if `reportRegistry` has
more than one session (`Tonight.tsx:75`).

**User CANNOT but needs to:**
- **Click through to any real candidate.** Every `CandidateCard` links to `/stock/${symbol}`
  (`CandidateCard.tsx:37`), but `Stock.tsx:22` looks the symbol up only in `ALL_CANDIDATES`
  (`fixtures.ts:232`, the 6-symbol fixture set: BANKA/VLEGOV/FILATEX/TRENT/ZOMATO/RATEGAIN).
  None of the 268 real `tonight_2026-08-28.json` symbols are in that array. Clicking any real
  candidate card on Tonight (which is now the primary content, per `Tonight.tsx:20-26`) lands
  on "No symbol selected" (`Stock.tsx:25-35`). This is the single largest dead end in the app —
  it breaks the scan→judge workflow at the second click.
- Watchlist drift and Yesterday's Calls are inert lists — no way to open a candidate from
  either the drift row (`Tonight.tsx:150-160`, no `Link`) or clarify it's fixture-only beyond
  the label.
- No filter/sort on Tonight itself — a user scanning 268 candidates across setup groups has no
  way to narrow within a group (has to go to Candidates for that).

**Honesty-layer verdict: PASS**, with one caveat. Real vs illustrative is distinguished at
point of use for every section: header/setups/footer are labelled real inline
(`Tonight.tsx:108`, real scan attribution), Yesterday's Calls and Watchlist Drift both carry
an explicit "Illustrative — ... backend not built" banner directly above the content
(`Tonight.tsx:135-137`, `148`), and Regime falls back to an explicitly dimmed/labelled
"Illustrative preview" block when `regimeBuilt` is false (`RegimeStrip.tsx:33-64`). Caveat:
the per-candidate real/illustrative distinction inside a setup group relies entirely on the
small caption at the bottom of each `CandidateCard` (`CandidateCard.tsx:88-100`) — on Tonight
today every card is real (`dataSource: "real_scan_raw"`), so this isn't hit, but nothing
prevents a future mixed group from reading as uniformly real unless a reader checks each card.

**Defects:**
- `Tonight.tsx:42-52` re-implements `toCandidate()` from `tonight.ts:115-138` inline (a second,
  slightly different mapping — it drops `detectorTrust` and `activityScore` entirely when a
  non-default session is picked via `reportRegistry`). Any session other than the
  `DEFAULT_REPORT` loses the trust/activity badges on `CandidateCard`.

## Candidates (`src/screens/Candidates.tsx`)

**User CAN:** filter by setup type and lifecycle stage (`Candidates.tsx:96-113`); sort by
best score / coverage / most recent (`Candidates.tsx:17-23`, `115-128`); see the
opportunity-landscape scatter for scored (fixture) candidates, with an explicit disclosure of
how many real candidates were excluded from the plot and why (`Candidates.tsx:137-142`); see
all 268 real + 9 fixture candidates as cards (`Candidates.tsx:15`, `148-150`).

**User CANNOT but needs to:**
- Click through to a stock page for any of the 268 real candidates — same dead end as Tonight
  (`CandidateCard.tsx:37` → `Stock.tsx:22`). Given Candidates is the "judge one" step of the
  workflow, this is where it hurts most: a user filters down to a real candidate, clicks it,
  and gets nothing.
- Filter/sort by the real raw-scan fields (RVOL, RS rank, contraction, ADR%) that
  `rawStats`/`rsRank`/`rvol` etc. actually carry (`fixtures.ts:76-86`). The only sorts offered
  (`best_score`, `coverage`, `recency`) either don't apply to real rows (`best_score` sorts
  all 268 real rows to the bottom, `scoreSum` returns `-Infinity` for undefined scores —
  `Candidates.tsx:56-61`) or are a weak proxy (`coverage` = count of stat fields, not stat
  quality — `Candidates.tsx:31-37`). A user wanting "show me the highest-RVOL real candidates"
  has no control for it.
- Search by symbol — no text filter anywhere on this screen.

**Honesty-layer verdict: PASS.** Scatter exclusion count and reason are disclosed inline
(`Candidates.tsx:138-141`); the candidate count line explicitly separates "real scan" count
from "fixture rows appended" (`Candidates.tsx:148-150`); every card still carries its own
dataSource caption per `CandidateCard.tsx:88-100`.

## Stock (`src/screens/Stock.tsx`)

**User CAN:** for one of the 6 fixture symbols only — see price chart with real bhavcopy
history when available or an explicit synthetic-data warning when not (`Stock.tsx:74-97`,
`StockChart.tsx:68-71`); see the Quality Stack decision panel, contributor bars, regime chip,
setup evidence with named numbers, and prior-call history (`Stock.tsx:99-129`).

**User CANNOT but needs to:**
- **Open any real candidate at all.** As established above, `Stock.tsx:22`
  (`ALL_CANDIDATES.find`) never matches a real symbol. For 268 of the ~277 total candidates
  in the app, the "judge one stock" step of the trader's workflow is entirely unreachable —
  this is not a degraded view, it is a hard wall ("No symbol selected", `Stock.tsx:25-35`).
  This single lookup line is the root cause; `CandidateScatter.tsx:69`,
  `CandidateCard.tsx:37`, and `History.tsx:94` (via `REAL_CALLS`) all navigate to
  `/stock/:symbol` assuming it works.
- Replay button is permanently disabled with a tooltip explaining why
  (`Stock.tsx:130-136`) — correctly labelled, not a silent dead end, but still a visible
  "can't do this yet" the user hits on every stock page.

**Honesty-layer verdict: FAIL for the majority case, PASS for the minority case it can
render.** The screen itself, when reachable, is honest (dataSource banner at
`Stock.tsx:62-67`, chart fallback note at `91-97`). But because the lookup only covers fixture
symbols, the honest answer a real-candidate click gets is a generic "No symbol selected" —
which does not tell the user *why* (real scan data exists but isn't wired into this lookup).
That's a silent-feeling dead end, not a labelled gap.

## History (`src/screens/History.tsx`)

**User CAN:** see real outcome-joined calls (`REAL_CALLS`, `outcomes.ts`) with win/loss/
unresolved counts (`History.tsx:27-29`, `83-86`); see an explicit warning banner that
net-of-cost bps are not populated yet, with the specific reason (`History.tsx:62-77`); click
through to a symbol's stock page (`History.tsx:92-95`).

**User CANNOT but needs to:**
- Click through successfully for any symbol not in the 6-fixture set — same root-cause dead
  end as above, hit from a third entry point (`History.tsx:94` → `Stock.tsx:22`). Given
  `REAL_CALLS` is sourced from the real research event store, most of its symbols are almost
  certainly not in `ALL_CANDIDATES`.
- Filter/sort/search History rows — it's a flat list capped at 80 most-recent
  (`History.tsx:26`, `117-123`) with no way to jump to a specific symbol, date range, or
  setup type.
- Only one session's report is linkable from "Past reports" (`History.tsx:48-54`, hardcoded to
  `SESSION.date`/`"/"` ) — not a real multi-report history despite the screen's name.

**Honesty-layer verdict: PASS.** The net-bps gap is disclosed with the exact writer/coverage
reason (`History.tsx:69-76`), not glossed over. Losses get identical treatment to wins per the
manual's stated rule (`History.tsx:9-11` comment, and the render loop at `88-115` treats all
three outcome classes uniformly).

**User CANNOT but needs to (or rather, correctly cannot, gated by the plan — see below):**

(`Research.tsx:85` "Expectancy numbers need N5 experiments"; negative findings show real
Blocked/Review status from the trust table, `142-153`).

## Settings (`src/screens/Settings.tsx`)

**User CAN:** toggle Beginner/Pro display mode (`Settings.tsx:27-40`); see real session stats,
real frozen cost/label/universe-gate config, and a real per-detector trust table
(`Settings.tsx:43-129`).

**User CANNOT but needs to:**
- Edit any weight, gate, or threshold — explicitly and correctly disclosed as out of scope,
  with the exact workaround path named (`Settings.tsx:136-142`: "Editing them today means
  changing the values passed into `unidesk/momentum` call sites directly"). This is a stated
  limitation, not a hidden one — **not a defect**, it's an honest scope cut.

**Honesty-layer verdict: PASS.** No fixture data disguised as real; the one remaining static
reference (`SESSION.date`/`universeScanned` from `fixtures.ts`, `Settings.tsx:5,51-55`) is the
2026-07-03 fixture session, not tagged real/illustrative on this screen — see defect below.

**Defects:**
- `Settings.tsx:51-59` renders `SESSION.date` / `SESSION.universeScanned` /
  `SESSION.pctAboveEma50` from `fixtures.ts:235-242` (the 2026-07-03 fixture session), while
  the rest of the app (Tonight, Candidates) has moved on to the 2026-08-28 real session
  (`tonight.ts:25`). This "Session data" card is stale and unlabelled as such — a user reading
  Settings could reasonably believe today's session is 2026-07-03, 2,563 universe, when the
  real current session is 2026-08-28. Minor honesty-layer gap: this is the one card on this
  screen not visibly flagged real/stale.

## Top 10 fixes, ranked by user impact

1. **Fix the Stock lookup to include real candidates.** `Stock.tsx:22` — change
   `ALL_CANDIDATES.find(...)` to also search `REAL_CANDIDATES` (from `tonight.ts:145`) before
   falling back to fixtures, and adjust `DecisionCard`/`SetupEvidencePanel`/`StockChart` to
   handle the real-candidate shape (no `trigger`/`invalidation`/`namedNumbers`/`company`).
   This is the fix that unblocks "judge one candidate" for 268 of ~277 candidates across three
   entry points (Tonight, Candidates, History). Everything else on this list is secondary to
   this.
2. **Give the real-candidate Stock view a decision panel that doesn't fake scores.**
   `DecisionCard.tsx:27-29` defaults undefined `stockStrength`/`setupQuality`/`entryTiming` to
   `0` — once fix #1 lands, a real candidate opened this way would render a Quality Stack
   showing all-zero scores, which reads as "this stock scored zero on everything," a worse
   honesty failure than the current dead end. Needs a raw-stats-only decision panel variant
   (mirroring `CandidateCard.tsx:53-69`'s `hasScores` branch) before #1 ships.
3. **Add symbol search on Candidates.** `Candidates.tsx:96-113` has no text filter; with 268
   real candidates in a filtered/sorted list, finding one specific symbol requires scrolling or
   using the setup-type filter as a proxy. File: `Candidates.tsx`.
4. **Add real-field sort/filter to Candidates** (RVOL, RS rank, contraction, ADR%) —
   `sortCandidates` (`Candidates.tsx:28-47`) only has scored-fixture-oriented sorts; the 268
   real rows are functionally unsortable by anything meaningful to a trader deciding which to
   look at first. File: `Candidates.tsx`.
5. **Un-stale the Settings session card.** `Settings.tsx:51-59` — swap `SESSION` (fixtures.ts,
   2026-07-03) for `REAL_SESSION` (tonight.ts, 2026-08-28), or tag it "fixture/demo session"
   if intentionally kept as a fixture reference. File: `Settings.tsx`.
6. **Make Watchlist Drift rows clickable.** `Tonight.tsx:150-160` renders symbol + note with no
   `Link` — inconsistent with every other symbol mention in the app being a navigation target.
   Low cost, matches existing pattern. File: `Tonight.tsx`.
7. **Reconcile Tonight's inline candidate mapper with `tonight.ts`'s.** `Tonight.tsx:42-52`
   drops `detectorTrust` and `activityScore` that `toCandidate()` in `tonight.ts:115-138`
   includes — any non-default session picked via the session switcher
   (`Tonight.tsx:75`) silently loses the Blocked/Review and Activity Score badges. Import and
   reuse `toCandidate()` instead of re-implementing it. File: `Tonight.tsx`.
8. **Add a per-candidate real/illustrative badge that survives mixed groups.** Today it works
   because Tonight's groups are currently all-real, but nothing structural stops a future group
   mixing real and illustrative cards silently beyond the per-card caption
   (`CandidateCard.tsx:88-100`). Add a group-level "N real / M illustrative" count next to each
   setup-type header (`Tonight.tsx:114-121`) as a second line of defense.
9. **Add a multi-session picker to History.** `History.tsx:48-54` hardcodes one report link;
   the screen's own text promises "past nightly reports" (plural) but only ever shows one.
   Already flagged as a known gap in the code (`History.tsx:120-122`) — worth prioritizing once
   more sessions exist, since History is meaningless as a review tool with just one date.
10. **Coverage-sort tie-break** — `Candidates.tsx:31-37`'s `coverage` sort counts fields, not
    quality of those fields (e.g. a real row with 6 `rawStats` outranks a fixture row with 3
    `namedNumbers` even if the fixture row's setup is materially stronger). Low priority, minor
    misleading-ranking risk. File: `Candidates.tsx`.

## Things that look broken but are actually correct-by-design

- **Research's ablation ladder shows all-null expectancy** (`Research.tsx:17-25`). Per the
  integration plan, Research is row 5 of the cadence table and explicitly gated
  **NO-GO** until N5 is lifted (`UI_BACKEND_INTEGRATION_PLAN.md:69`, "do not wire until N5 is
  lifted"). The archive-coverage/negative-findings top half of the screen is correctly wired to
  real data; only the ladder itself stays illustrative, and it's labelled as such
  (`Research.tsx:85`). Not a bug.
- **Regime strip showing "Regime not built yet"** with a dimmed illustrative preview
  (`RegimeStrip.tsx:33-64`) is driven by the real `honesty_footer.regime_built === false` flag
  from the actual 2026-08-28 report (`Tonight.tsx:99-100`, `tonight.ts:165`). This is the
  intended behavior per the plan's honesty-footer rule (`UI_BACKEND_INTEGRATION_PLAN.md:78-85`)
  — the UI is doing exactly what "never a silent, confident-looking table" requires. Not a bug.
- **Yesterday's Calls / Watchlist Drift staying on fixtures** (`Tonight.tsx:132-162`) — the
  plan gates History (row 4, outcome-join) behind Opus's stage-1 adjustment-guard conditions
  (`UI_BACKEND_INTEGRATION_PLAN.md:68`), and there's no watchlist backend named anywhere in the
  plan. Both are visibly bannered illustrative on-screen. Not a bug — though note History.tsx
  itself *has* moved to real `REAL_CALLS` (outcomes.ts) since this plan section was written on
  2026-08-30; Tonight's Yesterday's Calls panel specifically has not been re-pointed at that
  same real source and still uses the old `YESTERDAYS_CALLS` fixture
  (`Tonight.tsx:9`, `140`) — **worth flagging as a possible follow-up**, not because the plan
  requires it to stay illustrative, but because a real source (`outcomes.ts`) now exists that
  Tonight doesn't use. Marking this `Unverified: whether Tonight's Yesterday's Calls not
  reusing REAL_CALLS is an intentional scope cut or an oversight` — the plan doesn't say either
  way for this specific panel.
- **No trigger/invalidation, quality scores, lifecycle stage, or company/sector name on real
  candidates** (`fixtures.ts:47-56` comments, `tonight.ts:115-138`) — explicitly documented as
  fields the real scan doesn't compute yet, left `undefined` rather than fabricated, with
  `CandidateCard` rendering a raw-stats fallback (`CandidateCard.tsx:53-69`) instead of a fake
  Quality Stack. Correct application of the `dataSource` convention. Not a bug.
- **Stock's Replay button permanently disabled** (`Stock.tsx:130-136`) — tooltip names the
  exact blocker ("needs the U-P0.5 recorder's owner-run live session — not available yet").
  Correctly labelled, not a silent dead end.
- **Settings has no config-editing UI** (`Settings.tsx:136-142`) — explicitly stated as
  out-of-scope with the manual workaround named. Matches plan cadence row 6 ("config
  surfacing only"). Not a bug.
